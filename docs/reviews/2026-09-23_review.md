## Architecture & Boundary Health

The codebase adheres strictly to Hexagonal Architecture:
1. **Core Domain (`src/worksisyphus/core/domain/`)**:
   - `models.py`, `rules.py`, `plan.py`, `gates.py`, `ats_matcher.py`.
   - Domain logic is pure and free of disk I/O, subprocess calls, or network dependencies.
2. **Ports (`src/worksisyphus/ports/`)**:
   - `CompilerPort` (`compiler.py`): pdflatex compiler interface.
   - `AtsExtractorPort` (`parser.py`): PDF text extraction interface.
   - All legacy persistence (`StoragePort`), VCS (`GitGuardPort`), and rubrics ports have been cleanly excised.
3. **Adapters (`src/worksisyphus/adapters/`)**:
   - Inbound: Modular CLI handlers in `adapters/inbound/cli/handlers/` and shared `helpers.py`.
   - Outbound: `latex/` (`PdfLatexCompiler`), `pdf/` (`PdfMinerAtsAdapter`), `filesystem/` (`profile_loader.py`).
4. **Facades (`src/worksisyphus/*.py`)**:
   - Preserved for backward-compatibility with existing tests and scripts.

## Detailed Findings

### High Severity: Canonical Build ATS Date-Collision Bug
- **Issue**: Running `uv run worksisyphus compile` generates a 3-page canonical resume where line 222 produces:
  `Warning: horizontal overflow: 117.0pt too wide at tex line 222`
  This causes `test_compiled_resume_ats_extraction` and `test_compiled_resume_passes_all_gates` to fail with:
  `AssertionError: ATS check failed for compiled: ("'GeoPandasDecember 2024' extracted with no whitespace before the date; that keyword will not match",)`
- **Root Cause**: In `profile.json`, the project `crime-mapper` has a compound title:
  `"name": "Crime Analytics \\& Forecasting Platform / Crime-Mapper Boston"` (60 chars) combined with `"tech": "Python, Streamlit, Prophet, Scikit-learn, GeoPandas"` (51 chars).
  In Jake's template, `\resumeProjectHeading` uses a single left-aligned tabular column (`\begin{tabular*}{0.97\textwidth}{l@{\extracolsep{\fill}}r}`). Because the row cannot wrap, the left column spills 117pt over the right margin, directly overlapping `{December 2024}`. The PDF text extractor extracts `GeoPandasDecember 2024` with no whitespace, violating the `MERGED_DATE_RE` gate.
- **Proposed Fix**: Propose to Simon to shorten the compound title to either `Crime Analytics \\& Forecasting Platform` or `Crime-Mapper Boston`.

### Medium Severity: Ghost References to Decommissioned SQLite CLI
- **Issue**: Several error messages and internal function signatures still reference `uv run worksisyphus db export-profile` or SQLite parameters:
  1. `src/worksisyphus/adapters/outbound/filesystem/profile_loader.py` (lines 48-51):
     `Profile not found: ... If missing, recover from database with uv run worksisyphus db export-profile.`
  2. `src/worksisyphus/core/rendering/latex.py` (lines 71-73):
     `fix profile.json (recover it with uv run worksisyphus db export-profile --force)`
  3. `tests/test_profile.py` (line 67):
     Asserts `"db export-profile" in str(excinfo.value)`
  4. `src/worksisyphus/core/use_cases/application.py`:
     Contains `_resolve_db_path()` and `cross_check_contact_against_db(..., db_path=...)`, which are no longer needed.
- **Recommendation**: Update error messages to reference editing `profile.json` directly, and streamline contact validation naming in `application.py`.

### Low Severity / Feature Enablers: Auto-Apply Readiness Architecture
- **Issue**: The user's eventual objective is "automatically applying" to jobs. The system currently terminates at PDF generation, ATS verification, and folder freezing in `applications/`.
- **Architectural Gaps for Auto-Apply**:
  1. **Job Application Submission Port**:
     Missing an abstract `ApplicationSubmitterPort` (or `JobBoardAdapter`) to decouple form interaction (Playwright / Greenhouse / Lever / Workday) from `apply()`.
  2. **Screening Question Knowledge Base**:
     Auto-applying requires answering standard application questions (e.g. work authorization, US citizenship, sponsorship needs, years of experience, location/relocation preferences, demographic questions). Currently `profile.json` only contains resume content. A structured candidate profile configuration (e.g. `application_answers.json` or a `candidate` section) is needed so auto-apply agents do not hallucinate answers.
  3. **Application Lifecycle State Expansion**:
     `meta.json` currently tracks `applied`, `phone_screen`, `onsite`, `offer`, `rejected`. Automated submission will require tracking intermediate states like `drafting`, `submitting`, `failed_submission`, external job board IDs, submission timestamps, and confirmation URLs.
